# Extreme-RGMT Stage-I: current reproduction record

## Data preparation

The local smoke corpus uses 40 G1-retargeted LAFAN1 clips from the Hugging Face dataset `lvhaidong/LAFAN1_Retargeting_Dataset`, under the dataset's CC BY-NC-ND 4.0 terms. Keep the source attribution and license with any research use; do not redistribute transformed clips without checking the license terms. The original CSVs and generated NPZs are local ignored files under `data/`.

CSV layout is 30 Hz `[root_xyz(3), root_quat_xyzw(4), G1 joint positions(29)]`. Convert with the G1 MJCF matching this retarget, preserving its joint order:

```bash
python scripts/convert_lafan1_to_pmt.py \
  --input data/lafan1_g1 --output data/pmt_npz \
  --mjcf /path/to/matching/g1_29dof.xml --src-fps 30 --fps 50
```

The converter resamples root/joints, runs MuJoCo FK for the 14 PMT tracked bodies, and writes `fps`, `joint_pos`, `joint_vel`, `body_pos_w`, `body_quat_w` (xyzw, with explicit `quat_order=xyzw` metadata), `body_lin_vel_w`, `body_ang_vel_w`, plus `body_names` and `joint_names`. It maps CSV joint channels into the Isaac articulation order. This mapping is required because the raw CSV order and Isaac importer order differ. The launcher rejects files with missing or mismatched `joint_names` and any quaternion convention other than `xyzw`. This is a smoke corpus, not the paper's AMASS/XtremeMotion/Xsens training mix. The selected MJCF came from a neighboring local checkout and was read-only; it is not vendored here.

## Stage-I mapping and gaps

The policy implementation and values live in `extreme_rgmt/models.py`, `configs/extreme_rgmt_stage1.yaml`, and `scripts/train_stage1.py`. The runner maps PMT's RGMT observation groups to the paper actor/critic sets and applies the paper's PPO rollout/update values. The FSQ level count (5 per scalar) and attention head count (4) are explicit assumptions because the paper does not specify them.

The current PMT task is an integration backend, not a fully faithful reproduction. Runtime inspection confirmed the 29-joint Isaac order differs from the CSV order; the converter now applies a name-based permutation and the launcher checks both file metadata and runtime articulation names. The initial zero-action diagnostic exposed a root-quaternion convention mismatch: MuJoCo stores WXYZ while Isaac Lab consumes XYZW. The converter now keeps WXYZ internally for angular-velocity finite differences, writes XYZW poses, and tags their order. The 40 motions and 902 Stage-II clips have been regenerated. With the retarget-matched URDF, the 30-step Isaac Lab diagnostic now starts with only 1–14 mm tracked-body error and no terminations; errors then grow under zero residual actions (body error max 0.80 m by step 30, joint L2 mean 1.02 rad), which is expected from an uncontrolled robot and does not validate a learned policy. This resolves the prior reset/FK mismatch; subsequent PPO runs now execute, but learned tracking remains worse than the zero-residual baseline.

## Adaptive-sampling fidelity audit (2026-11-06)

The paper specifies temporal-bin difficulty statistics with an EMA, clipping/normalization, and a uniform sampling component (Sec. IV-C, Eqs. 12–13). The current Stage-I launcher instead selects PMT `bin_adaptive`: at 50 Hz it uses 1-second bins, `alpha=0.001`, `beta=2`, `uniform_ratio=0.1`, updates every 240 simulation steps, and smooths across as many as 50 bins. PMT estimates empirical failure rates from terminated versus non-terminated episodes, raises rates to `beta`, mixes a uniform component, first samples a motion using its hardest-bin score, and then samples a bin within that motion. This is a concrete algorithmic difference from the paper's stated clipped/normalized bin-score distribution; it is inherited backend behavior, not evidence that PMT is the paper implementation.

The paper does not report the bin duration, EMA coefficient, clipping ceiling, uniform-mixture value, or smoothing kernel. It mentions tracking-error or failure frequency, while the selected PMT sampler currently updates difficulty from termination outcomes only. These missing hyperparameters prevent a uniquely determined paper-exact sampler, so the PMT sampler remains an explicit approximation pending an authoritative implementation or supplementary specification. The paper's 0.2 m criterion is for evaluation rollout success; it does not specify the training early-termination threshold. The active flat G1 task sets its end-effector position termination threshold to 0.4 m (overriding the base config's 0.25 m), another backend assumption currently left unchanged.

## Paper DR audit (Table II, 2026-11-06)

The paper's Table II lists ground friction `[0.10, 1.75]`, added base mass `[-3, 6] kg`, torso CoM offset `x=[-0.025,0.025] m` and `y,z=[-0.05,0.05] m`, motor strength and PD gain scales `[0.8,1.2]`, motor zero offset `[-0.01,0.01] rad`, armature scale `[1.0,1.05]`, and external pushes every `[1,3] s`. Observation noise magnitudes are gravity `0.05`, angular velocity `0.2 rad/s`, joint position `0.01 rad`, and joint velocity `0.5 rad/s`. Command perturbations are base linear velocity `±0.5 m/s`, base angular velocity `±0.52 rad/s`, gravity direction `0.05`, and joint pose `±0.1 rad`.

Against pinned PMT `RGMT-G1-v0`, static source inspection confirms matching torso CoM ranges, joint default-position offset, push interval, angular-velocity/joint-position/joint-velocity noise magnitudes, and paper actor-noisy/critic-clean separation. The target adapter now overrides static/dynamic friction ranges to `[0.10,1.75]`, adds a `[-3,6] kg` mass event on the pelvis (the explicit implementation interpretation of “base mass”), scales motor effort limits by `[0.8,1.2]` using one independent factor per environment shared across joints, scales PD stiffness and damping by `[0.8,1.2]`, scales armature by `[1.0,1.05]`, and injects the paper noise bounds into actor proprioception and reference-window velocity, gravity, and joint-pose channels. Existing PMT terms retain the paper CoM offset, motor zero offset, and 1–3 s push interval. Remaining differences: PD gain factors are sampled independently per joint and for stiffness/damping, which may differ from a single shared scale if that was intended; the friction table gives one range, so applying it to both static and dynamic friction is an explicit assumption; PMT push velocity magnitudes remain its defaults because the paper specifies only push interval, not push magnitude. Event wiring and noise bounds have unit coverage, but actual event execution, effort-limit write behavior, and observed noise distribution still need simulator validation.

The converter's 29-joint CSV order exactly matches the movable-joint order in PMT's checksum-verified `unitree_description/urdf/g1/main.urdf` (static XML check, all 29 names and indices). PMT's multi-motion command config does not declare an independent joint-name remapping; it consumes motion arrays directly against articulation tensors. The final articulation/action-manager order still requires a runtime check after the simulator starts. The launcher default now points at the actual pinned `third_party/PMT-pinned/` path.

## Policy implementation audit (2026-11-06)

A source-level comparison with Sec. III-C and Table III confirms the implementation uses separate state/action/reference MLP branches with widths `[64,128,64]`, `[29,64,64]`, and `[38,128,64]`; per-branch LayerNorm; alternating action/state history tokens with a causal mask; a 21-token command cross-attention path; two 32-scalar quantized outputs; a 29D residual action head; asymmetric privileged critic; and the listed actor/critic MLP widths. The PMT action term sets unit residual scale and tracks the reference pose as its offset, matching `q_target = q_ref + a`.

Implementation assumptions and unresolved details remain: the paper omits attention-head count and FSQ scalar level counts, so this code uses four heads and five odd levels per scalar; exact actor-critic tensor wiring still requires a live RSL-RL environment initialization and rollout. Unit tests cover shapes, gradients, causal attention, and FSQ straight-through gradients, but do not validate paper performance.

### Residual-action ablation

The paper gives the action interface as \(`q_target = q_ref + a`\). The launcher therefore defaults to unit residual scale in radians, with `--residual-scale pmt` retaining PMT/Unitree per-joint scale for controlled comparison. This is an interface-level fidelity choice; stable tracking still requires rollout validation. The 200-iteration PMT-scale run after the coordinate fix completed 614,400 transitions but did not learn useful tracking (final mean episode length 8.13 steps, joint-position error 2.46 rad, EE termination 97.4%).


The unit-scale PPO ablation using the upstream initial action standard deviation of 1.0 also collapsed: 614,400 transitions, final mean episode length 4.16, joint-position error 2.69 rad, and 98.4% EE-position terminations. Initial action standard deviation is now configurable for controlled stability experiments; the paper does not report this value.

A third 200-iteration controlled run used unit residual scaling and initial action std 0.05 (paper does not specify initial std). It completed 614,400 transitions and the final iteration reported mean episode length 21.86, joint-position error 2.04 rad, body-position error 0.222 m, and 88.1% EE-position terminations. This is more stable than std 1.0 but remains a failed tracking policy; none of these short ablations is a reproduction checkpoint.

An initial implementation disabled Isaac Lab corruption flags but left custom noise functions installed, so those first evaluation numbers were invalid and have been superseded. The evaluator now restores clean proprioception and command-window functions in addition to disabling domain randomization.


An earlier 32-env evaluation used adaptive motion/frame sampling and treated timeout as success. It did not fix the motion IDs or starting frames and did not count natural clip completion; those numbers are superseded by the controlled evaluation below.

The 1,000-iteration unit-scale/std-0.05 PPO run completed 3,072,000 transitions and saved `logs/extreme_rgmt_stage1/2026-11-06_13-37-54/model_999.pt`. ## Controlled deterministic tracking evaluation (2026-11-06)

The Stage-I launcher now has a fixed-motion evaluation command config. It assigns motion IDs round-robin when the environment count covers the input set, or samples IDs evenly across a larger set; every reset uses the configured fixed reference frame. PMT performs the usual reference-buffer and articulation reset. In evaluation mode `chunk_length=0` so each runtime motion ID maps one-to-one to the manifest file. The evaluator checks the wrapped live `ManagerBasedRLEnv`, randomized events in both the active EventManager and its config, the already-built ObservationManager callables/noise, the exact motion/frame tensors, and the runtime source-file ordering. It disables PMT's internal long-motion chunking in evaluation so a motion ID corresponds to exactly one manifest file. The actor, critic, and action tensor interfaces are unchanged. Results are written as per-motion JSON under `logs/extreme_rgmt_eval/`.

All comparisons below use seed 17, 40 environments, frame 0, 3,000 control steps, clean observations, and no domain randomization. They are diagnostic fixed-start tests, not the paper's five randomized rollouts. `tests/test_evaluation.py` covers wrapper unwrapping, fixed schedules, live observation noise, event-manager modes, exact assigned motion/frame IDs, and file-order mismatch. Final full suite: 47 passed. `py_compile` and `git diff --check` pass.
## Residual-action interface runtime check (2026-11-06)

The actor action is applied by a local `ReferenceResidualJointPositionAction` that computes `q_ref + scale * action` from the live command tensor on every environment step. This makes the paper's action equation explicit and independent of PMT's mutable-offset adapter. A two-environment headless Isaac Sim reset diagnostic verified the zero-residual target against the exact pre-step reference tensor: maximum absolute error `0`, and neither environment terminated on the first step. The stock PMT command implementation also updates its Torch action offset on command updates; therefore the earlier suspicion that a stale offset caused the poor checkpoint is not supported. The explicit action term is an interface clarity/verification improvement, not an identified explanation for the prior learning failure. Existing checkpoints predate this explicit implementation and require re-evaluation before drawing comparisons.

A post-change PPO smoke run on 8 environments completed one iteration (192 transitions) and wrote `model_0.pt` at `logs/extreme_rgmt_stage1/2026-11-06_15-00-24/model_0.pt`. This confirms the custom action term works through RSL-RL collection and optimization. The run is only a launcher smoke test: its first-update approximate KL was 18.22 with clip fraction 0.944, so this tiny batch is unsuitable for learning conclusions and warrants monitoring at the paper-scale environment count. It does not establish improved tracking.

## Stage-II PACE/STAR loss-path audit (2026-11-06)

Reviewing the pinned PPO implementation exposed a concrete PACE objective leak: the first Stage-II adapter mixed mastered and acquisition transitions in PPO minibatches and zeroed mastered advantages, which suppressed their policy-ratio term but still let mastered samples contribute to critic value loss and entropy regularization. The paper states mastered samples contribute only the frozen-policy action-MSE consolidation objective (Eq. 14–15). The adapter now builds PPO minibatches from acquisition transitions only, normalizes STAR advantages only over acquisition data, and supplies a separate mastered-state batch solely to the policy auxiliary-loss hook. This leaves the PPO surrogate, critic, and entropy terms on acquisition data while preserving gradients for the mastered action-MSE term. Focused tests verify acquisition-only PPO batches, side-channel alignment, and trainable-policy/frozen-reference gradients. A one-iteration headless Isaac Sim/PPO smoke run then completed 48 transitions and saved `logs/extreme_rgmt_stage2/2026-11-06_15-35-22/model_0.pt`. It used only two local dance clips split one-per-role for software integration, not a paper-derived mastered/challenging partition. This confirms the revised loss path executes through the real runner; it does not establish PACE/STAR learning performance or a valid Stage-II result.

## Reference-following control diagnostic (2026-11-06)

A fresh five-control-step headless diagnostic was run on `dance1_subject1.npz` with two environments. The diagnostic now records Isaac runtime joint gains/effort limits, reference and measured joint states, and each actuator group's computed/applied effort. Runtime gains were nonzero (per-joint stiffness ranged from 14.25 to 99.10; damping from 0.91 to 6.31) and effort limits were populated (5 to 139 Nm), despite the importer warning that the URDF itself contained no gains. Computed and applied efforts matched in the logged samples, and the first-step torque values were below the listed limits; this does not support missing PD actuation or immediate torque saturation as the cause of tracking loss. On this clip the maximum selected-body position error grew from 0.0174 m after one control step to 0.1360 m after five, while mean joint-error L2 grew from 0.142 to 0.735 rad. This short, randomly reset clip diagnostic is evidence about actuator wiring only, not a performance evaluation. Next diagnosis should quantify reference joint/body velocities and per-step reference frame advancement against the 50 Hz control clock, then compare the retarget model and PMT actuator dynamics. No controller parameter is changed on the basis of this diagnostic because the paper does not specify its Stage-I physics backend or PD gains.

A second diagnostic fixes the reset at motion 0, frame 100, disables randomization, and asserts every control transition. Over 30 steps, each policy action was processed against frame `k`, the zero-residual target matched that pre-step reference exactly (max error 0), and the next observation advanced to frame `k+1` (delta exactly 1) on every environment. This matches the Isaac Lab/PMT call order: action processing and physics precede `command_manager.compute()`, where PMT advances one 50 Hz frame. Thus a one-frame action/observation phase error is not supported by the current evidence. Despite the fixed, low-speed starting segment (initial max joint reference speed 0.0734 rad/s), mean joint-error L2 reached 0.9407 rad and selected-body position error peaked at 0.2327 m by step 30. The timing diagnostic therefore shifts the investigation toward reference-vs-simulation model/controller/contact mismatch. Effort saturation was zero in the first five measured control steps; this is not enough to rule out saturation later in a full motion. The exact diagnostic was run with `--eval-zero-action --eval-frame 100 --diagnose-reference-steps 30` on `dance1_subject1.npz`.

## URDF/MJCF inertial and contact follow-up (2026-11-06)

A name-based comparison of all 29 driven-link inertials in the converter's `data/g1_description/g1_29dof.xml` and the runtime `g1_29dof_rev_1_0.urdf` found maximum mass difference `4.4e-7 kg`, local center-of-mass difference `4.78e-8 m`, and inertia-tensor element difference `3.90e-8 kg m^2`; all 29 joint axes also match. The aggregate model mass differs by about `9.8e-7 kg`. For collision geometry, both descriptions use the same four 5 mm sole spheres on each ankle-roll link and matching shoulder cylinders; visual meshes are marked non-colliding in the MJCF where a simplified collision is provided. This substantially reduces the likelihood that gross URDF/MJCF inertial or foot-collision omissions explain the tracking gap, while engine contact/friction implementation may still differ.

A new `--diagnose-hold-reference-steps N` path holds the reset reference joint target constant while stepping PhysX directly, without advancing the motion command. It requires `--eval-zero-action` to ensure a fixed frame and disabled randomization. At motion 0/frame 100, foot contact force was zero on the first physics/control sample and about 164–173 N by control step 5–15; root drift reached 0.0617 m and mean joint-error L2 0.806 rad by step 15. This static-target test is deliberately not a tracking score because the floating base is not actively controlled and a frozen dance pose need not be in static balance. It does confirm contact is established and demonstrates that fixed joint targets alone do not hold the full-body state. The command and results are diagnostic only; no physical parameters have been tuned.

## Contact material and physics-step comparison (2026-11-06)

The clean evaluation runtime reports PhysX robot collider material values of static/dynamic friction `1.0` and restitution `0.0`; the plane config is also friction `1.0`, restitution `0.0`, with multiply combine mode. The MJCF model compiles with geom friction `[1.0, 0.005, 0.0001]` and default `solref=[0.02, 1.0]`; there is no explicit MuJoCo plane geom in the retarget MJCF itself. Thus the leading friction coefficients and bounce setting agree, but the full anisotropic/torsional friction model and contact solver are engine-specific and not directly equivalent.

The MJCF compiles with a 2 ms physics timestep; the PMT PhysX task defaults to 5 ms and four substeps per 20 ms policy step. Added `--physics-dt` to the Stage-I launcher; it sets decimation so the 20 ms policy period stays fixed. A same-motion, same-seed/frame, two-environment 30-step comparison at `--eval-frame 100` produced at step 30 mean joint-error L2 `0.9407 rad` / selected-body error peak `0.2327 m` at 5 ms, versus `0.9105 rad` / `0.2163 m` at 2 ms. The frame advance and target-alignment assertions also passed at 2 ms. This small diagnostic shows only a modest change and does not explain the tracking failure; it is not a controlled statistical evaluation. The remaining backend solver/contact-law mismatch and active actuator assumptions remain unresolved, and no values are presented as paper-prescribed.


## Five-rollout Stage-I stratification evaluator (2026-11-06)

`train_stage1.py --eval-paper-split` schedules five full rollouts per input motion, applies a 0.2 m root-height failure threshold, disables PMT's additional anchor-orientation and end-effector termination criteria, and queues trials under a hard `--num-envs` cap. The current diagnostic starts every rollout at frame 0, shuffles trial order with the requested seed, and disables observation noise and domain-randomization events. The paper says to use “five randomized rollouts” for each clip but does not specify what is randomized or where a rollout starts. Frame-zero starts and clean, unrandomized evaluation are therefore implementation choices, not confirmed paper details. The generated JSON records each start frame, outcome, and length. Its 80% split is mechanically valid for those recorded trials, but it is not yet established as the paper's randomized evaluation protocol.

The 902 generated LAFAN1 clips completed all 4,510 trials for each full-split run. The zero-residual reference-PD baseline had 35 successes, 4,475 failures, and 7 mastered clips. The 500-iteration checkpoint and the later 1,000-iteration checkpoint each had 30 successes, 4,480 failures, and 6 mastered clips; their mastered sets were identical, while the baseline differed by one clip. The baseline and 500-iteration report used the same seed, clip manifest, requested environment cap, trial count, threshold, and evaluator mode; this is a same-seed diagnostic comparison, not evidence of independent statistical significance. Report files: `logs/extreme_rgmt_eval/paper_split_lafan1_902clips_zero_action_seed17.json`, `logs/extreme_rgmt_eval/paper_split_lafan1_902clips_model499_seed17.json`, and `logs/extreme_rgmt_eval/paper_split_lafan1_902clips_model999_seed17.json`. Both learned checkpoints fail to outperform the reference-PD baseline on this observed metric. The 40-full-sequence evaluation is supplemental because the paper specifies splitting sequences longer than 10 s into 10-s clips before stratification. Only LAFAN1-derived clips are available locally; this is not the paper's multi-source split.

The implementation and pure schedule/partition tests are in `extreme_rgmt/evaluation.py` and `tests/test_evaluation.py`. The classifier verifies exactly five outcomes per clip and applies the 80% threshold. Stage II accepts the resulting report, but because the evaluation randomization details remain unspecified, its 6/896 input split is an integration artifact rather than a validated paper split. The one-iteration Stage-II run loaded all 902 clips, updated PACE progress, and wrote `logs/extreme_rgmt_stage2/2026-11-06_17-05-07/model_0.pt`; this is a data-path/runner check, not Stage-II convergence. Reproduction remains incomplete pending an evidence-based interpretation of randomized evaluation, a successful Stage-I base policy, multi-source data, and backend fidelity work.
